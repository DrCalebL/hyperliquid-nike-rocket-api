## Deviations from the spec (builder, for review)
1. **A `deferred` close job does not make the user busy** (spec 19.6 said pending/deferred). A deferred job waits
   for the recovery lane, and the lane yields to busy users: counting it would stall the lane on a possibly naked
   position until the 24 h expiry.
2. **Residual close ladder.** When the venue holds more than the row's share, `hl_close_with_verification` is NOT
   used: its partial-fill branch re-sizes to the whole venue position, which would close the user's own add (I1).
   `_close_share` runs the same C41 ladder but each rung sends only what is left of the share. The common case
   (venue <= share) uses `hl_close_with_verification(..., source='trading')` as specified.
3. **Max attempts** fail a job only for "not flat after the close" (spec 19.7 step 7); read errors and cancel
   failures stay `pending` until the 24 h expiry, so an HL outage cannot burn the attempts in a minute.
4. **Unusable credentials** fail the job at once (`CLOSE_JOB_FAILED`, critical + admin e-mail): no order is sent.
5. `CLOSE_RESIDUAL` e-mails the admin on the first not-flat attempt only (every attempt is still logged).
6. `CLOSE_KNOWN_SYMBOLS` (env, default `ADA/USDT`) is the follower's "symbol map" for the validator.
7. `tests/test_hl_rate.py` is outside T07's file list: its position_monitor text pin had to move with the monitor
   change the spec requires.
